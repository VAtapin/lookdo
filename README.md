# LOOKDO

> **LOOK. DO.**  
> **СМОТРИ. ДЕЛАЙ.**

LOOKDO — мультитенантная платформа, в которой один проект состоит из двух чётко разделённых частей.

## Часть 1 — платформа LOOKDO

Это `lookdo.app`: публичная B2B-страница продукта, регистрация и подписка владельцев бизнеса, Tenant account для системных настроек и Super Admin платформы.

Часть 1 уже строится как Laravel API + Vue 3 SPA/PWA. Её актуальное техническое задание: **[PART1_SAAS_PLATFORM.md](PART1_SAAS_PLATFORM.md)**.

Связанные инфраструктурные документы:

- **[DOMAIN_ARCHITECTURE.md](DOMAIN_ARCHITECTURE.md)** — tenant subdomains/custom domains/DNS/SSL;
- **[DEPLOYMENT_PLESK.md](DEPLOYMENT_PLESK.md)** — production deployment;
- **[BACKUP.md](BACKUP.md)** — backup/restore.
- **[SMS.md](SMS.md)** — SMS an Endkunden, Tariflimits und seven.io Delivery Reports.

## Часть 2 — Tenant App

Это брендированное мобильное приложение конкретного мастера/сервиса и его клиентов. Основной сценарий использования — телефон. Приложение может открываться на desktop, но проектируется mobile-first/app-like, а не как desktop dashboard или длинный сайт.

В одном Tenant App работают клиент и владелец/мастер; после авторизации мастер получает свои рабочие функции.

Единое актуальное ТЗ всей Части 2, включая шаблоны, Request Engine, Booking, календарь, клиентов, сообщения, уведомления, VK/Telegram/Viber/WhatsApp, AI, UI и цвета:

**[TENANT_APP_SPEC.md](TENANT_APP_SPEC.md)**

Конкретные профессиональные шаблоны находятся в **[`/templates`](templates/)**. Их README/template.json описывают только особенности профессии и не должны повторять общую архитектуру.

## Языки

Базовые языки платформы: **DE / EN / RU / UK** (немецкий, английский, русский, украинский). Tenant может включить только нужные ему языки публичного App.

## Главный принцип

LOOKDO не является маркетплейсом и не заставляет конечного клиента регистрироваться. Tenant получает собственное брендированное приложение на `<slug>.lookdo.app` и при желании на своём домене.

Типовой сервисный сценарий: клиент показывает задачу фото/видео → оставляет выбранные владельцем контактные данные → мастер получает обращение → отвечает и договаривается.

Типовой booking-сценарий: клиент выбирает услугу → свободную дату/время → оставляет требуемые владельцем данные → получает подтверждение и напоминания.
