# LOOKDO

> **LOOK. DO.**  
> **СМОТРИ. ДЕЛАЙ.**

**LOOKDO** — мультитенантная SaaS-платформа для сервисного бизнеса и мастерских. Конечный клиент не заполняет длинные анкеты и не получает автоматическую «цену из калькулятора»: он показывает мастеру задачу фотографиями или коротким видео, оставляет обязательный номер телефона и получает ответ живого специалиста.

Основной домен платформы: **lookdo.app**

## Текущее состояние

Часть 1 реализована как Laravel 13 API + Vue 3 SPA/PWA: публичный сайт, динамические тарифы, регистрация со словарным и AI-подбором существующего шаблона, tenant account shell, домены, Stripe-подписки, Super Admin, DE/EN/RU, legal/content editor, audit log и проверяемые резервные копии. Камера, заявки, работы и сообщения намеренно оставлены для Части 2.

Локальный запуск:

```bash
composer install
copy .env.example .env
php artisan key:generate
php artisan migrate --seed
npm install
npm run dev
php artisan serve
```

Для production/Plesk см. **[DEPLOYMENT_PLESK.md](DEPLOYMENT_PLESK.md)**.

## Главная идея

Клиент показывает — мастер смотрит и делает.

Типовой путь будущего tenant App:

**бизнес/работы → фото или видео задачи → обязательный телефон → заявка → уведомление мастеру → ответ → сообщения/push/звонок → договорённость**.

LOOKDO должен оставаться простым. Новая профессия **не создаёт новый frontend и новые экраны**. В системе есть один Request Engine и библиотека `request_template`. AI по свободному описанию деятельности подбирает лучший существующий шаблон; если точного адресного шаблона нет, используется основной шаблон деятельности.

Для деятельностей с записью LOOKDO дополнительно использует общий Booking/Calendar capability: **услуга → свободный слот → имя + обязательный телефон → Termin → reminders → повторный визит**, без регистрации конечного клиента.

## SaaS и домены

Каждый бизнес — отдельный tenant со своим брендом, цветами, контентом, заявками, сообщениями, отзывами, интеграциями и доменами.

**Каждый tenant автоматически получает постоянный платформенный адрес `<slug>.lookdo.app` сразу после регистрации/onboarding.** Собственный домен подключается дополнительно и не является обязательным для запуска.

Для платформенных tenant-поддоменов используется wildcard DNS/SSL:

`*.lookdo.app`

Пример:

- `leonid.lookdo.app` — платформенный адрес tenant;
- `leonid-deluxe.de` — дополнительный собственный домен того же tenant.

Оба адреса могут вести на один tenant; один выбирается как `primary_domain`. Полная обязательная архитектура доменов описана в **[DOMAIN_ARCHITECTURE.md](DOMAIN_ARCHITECTURE.md)** и должна учитываться уже в Части 1.

Первый реальный tenant — мастерская Леонида по перетяжке рулей. Никакой отдельной логики для Леонида нет: это обычный tenant, которому через Super Admin можно назначить нужный тариф бесплатно.

## AI-классификация деятельности

При регистрации владелец пишет деятельность обычными словами, например:

- «перетягиваю автомобильные рули»;
- «устанавливаю входные двери»;
- «ремонтирую стиральные машины».

LOOKDO ищет совпадения и близкие формулировки в словаре и использует AI как классификатор. AI **не создаёт новые шаблоны**: он выбирает только существующий `request_template`. При низкой уверенности пользователю показываются 2–3 подходящих варианта.

Приоритет выбора:

1. специализированный адресный шаблон;
2. основной шаблон деятельности;
3. если подходящего шаблона нет — поддержка: **«Не нашли подходящий шаблон? Напишите в поддержку — мы посмотрим и добавим.»**

## Клиентское приложение — Часть 2

Основная навигация остаётся минимальной и соответствует утверждённым UI-макетам:

**Главная · Работы · Основное действие · Сообщения**

Примеры «До/После» могут дополнительно находиться на Главной, но отдельный раздел «Работы» обязателен. Дополнительные состояния — камера/медиа, заявка отправлена, разрешение push, отзывы и контакты.

Booking не создаёт второе приложение и не ломает общую структуру Tenant App: для подходящего бизнеса он подключается как общий capability/CTA и использует общие сущности services, appointments, customers и communication.

## UI

Глобальная папка **[`/UI`](UI/README.md)** — обязательный визуальный эталон Tenant App. Конкретные шаблоны могут иметь собственные `hints/` и дополнительный мобильный reference в своей папке, но они **не меняют структуру общего приложения**.
