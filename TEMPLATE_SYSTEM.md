# LOOKDO — актуальная система шаблонов (обязательная для Codex)

> Этот документ **заменяет старую модель `category + variation` для runtime-шаблонов**. Старые разделы CODEX.md с жёсткими `variation` считать исторической логикой классификации, а не инструкцией по созданию frontend.

## 1. Главное правило

У LOOKDO есть **один базовый Request Engine и один app UI**. Профессии/деятельности не создают новый frontend.

Новый шаблон = конфигурация:

- тексты;
- CTA;
- photo/media slots;
- подсказки;
- hint images;
- набор универсальных полей;
- разрешение/рекомендация видео;
- AI-фразы;
- локализации.

Создание нового шаблона **не должно требовать** нового Vue-экрана, нового API endpoint, новой таблицы БД или отдельного controller.

## 2. Уровни шаблонов

### A. BASE REQUEST TEMPLATE

`templates/BASE_REQUEST_TEMPLATE.md`

Неизменяемое ядро: media flow → дополнительные данные → комментарий → обязательный телефон → отправка → success → push → messages.

### B. Основной шаблон деятельности

Это реальная деятельность бизнеса и одновременно fallback для неё.

Примеры:

- `automotive.general` — Автомобили и автосервис;
- `repair-finishing-installation.general` — Ремонт, отделка и монтаж;
- `appliance-repair.general` — Ремонт бытовой техники;
- `furniture.general` — Мебель;
- `garden.general` — Сад и участок;
- `cleaning.general` — Уборка и чистка;
- `bicycles.general` — Велосипеды;
- `advertising-signage.general` — Рекламные вывески и оформление.

Основной шаблон должен уже быть полностью рабочим. Клиент может использовать его без специализированного подшаблона.

### C. Адресный специализированный шаблон

Создаётся только там, где конкретная деятельность реально выигрывает от своих терминов, порядка фотографий, hint images или дополнительных полей.

Примеры:

- `automotive.steering-wheel-upholstery` — Перетяжка руля;
- `repair-finishing-installation.door-installation` — Установка дверей.

Такой шаблон наследует общий flow родителя и переопределяет только контент/конфигурацию.

## 3. Что такое «категория» теперь

Категория нужна для:

- группировки библиотеки;
- AI-поиска;
- навигации Super Admin;
- аналитики;
- fallback.

Категория **не определяет Vue-компонент**.

`variation` не является обязательной сущностью runtime. Вместо неё используется `request_template` с уникальным `code`.

## 4. AI-классификация

Onboarding спрашивает: **«Чем вы занимаетесь?»**

AI + словарь ищут лучший `request_template`.

Порядок:

1. exact/fuzzy match по AI-фразам;
2. shortlist подходящих шаблонов;
3. AI выбирает только из существующих шаблонов;
4. сохраняются `template_id`, confidence и source;
5. при низкой уверенности показать 2–3 варианта;
6. если адресный шаблон не найден, использовать основной шаблон деятельности;
7. если не найден даже основной: **«Не нашли подходящий шаблон? Напишите в поддержку — мы посмотрим и добавим.»**

AI не создаёт новые шаблоны сам.

## 5. Универсальная БД

Заявка не получает колонки `car_*`, `door_*`, `washer_*` в основной таблице.

```text
requests
- id
- tenant_id
- template_id
- customer_phone
- comment
- status
- created_at
```

Дополнительные значения:

```text
request_fields
- id
- request_id
- field_key
- value
```

Медиа:

```text
request_media
- id
- request_id
- slot_key
- media_role
- type
- sort_order
- path
```

Шаблон определяет допустимые `field_key`, `slot_key` и тексты.

## 6. Hint images

Каждый шаблон может иметь папку `hints/` со специализированными подсказками, например:

```text
templates/automotive/steering-wheel/hints/
templates/repair-finishing-installation/door-installation/hints/
```

Hint image — контент шаблона, а не новый UI.

## 7. UI — строго единый

Глобальные изображения `/UI` — главный визуальный эталон Tenant App.

Для конкретного адресного шаблона допускается свой дополнительный mobile-flow reference внутри папки шаблона. Он показывает содержание конкретного сценария, но **не отменяет `/UI`**.

Codex не имеет права:

- делать отдельный дизайн под профессию;
- превращать flow в длинную форму;
- менять нижнюю навигацию;
- создавать многошаговый wizard только потому, что у шаблона 5–6 photo slots;
- дублировать camera/upload/messages/push.

## 8. Tenant overrides

Tenant может упростить шаблон:

- изменить CTA/короткие тексты;
- скрыть необязательное поле;
- отключить/включить видео, если шаблон это допускает;
- изменить максимум фото в разрешённых пределах;
- добавить собственную короткую подсказку.

Tenant не может отключить обязательный телефон или изменить системную архитектуру flow.

## 9. Текущее решение по основным деятельностям

На текущем этапе именно эти основные шаблоны считаются приоритетными:

1. Автомобили и автосервис
2. Ремонт, отделка и монтаж
3. Ремонт бытовой техники — **единый шаблон для бытовой техники; не плодить отдельные шаблоны для стиралки/холодильника без реальной необходимости**
4. Мебель — **без «интерьера»; интерьерные/отделочные работы относятся к ремонту и отделке**
5. Сад и участок
6. Уборка и чистка
7. Велосипеды
8. Рекламные вывески и оформление

Специализированные адресные шаблоны уже есть/планируются там, где они действительно дают иной photo guidance.

## 10. Каноническое место

Все шаблоны и их контент хранятся в `/templates` и синхронизируются/seed-ятся в БД. Super Admin должен позволять редактировать runtime-копию, но Git остаётся каноническим исходником для разработки и ревью.
