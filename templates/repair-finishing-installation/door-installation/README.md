# LOOKDO — шаблон «Установка дверей»

**Код:** `repair-finishing-installation.door-installation`  
**Категория:** Ремонт, отделка и монтаж  
**Родительский шаблон:** `repair-finishing-installation.general`  
**Тип:** специализированный адресный шаблон  
**Приоритет:** высокий — один из первых реальных сценариев LOOKDO

## КРИТИЧЕСКОЕ ПРАВИЛО ДЛЯ CODEX

Этот шаблон должен быть реализован **строго в визуальной системе утверждённых макетов из папки `/UI`**.

Нельзя:

- менять app-like структуру экранов;
- превращать заявку в длинную веб-форму;
- делать отдельный wizard на много страниц;
- менять нижнюю навигацию;
- переносить camera/upload flow в другой UI;
- заменять карточки, bottom sheets и состояния из `/UI` типовым Bootstrap/Filament/landing интерфейсом;
- придумывать новую структуру экрана только потому, что шаблон относится к дверям.

Макеты `/UI` определяют **КАК выглядит интерфейс**, а этот шаблон определяет **ЧТО именно показывается и что просим сфотографировать**.

При конфликте между предположением разработчика и `/UI` приоритет имеют `/UI`, если это не противоречит безопасности, accessibility или явно зафиксированной бизнес-логике.

Для этого шаблона используются собственные hint-illustrations из `hints/`. Цветовая тема подсказок должна отличаться от автомобильного шаблона: **холодный сине-бирюзовый акцент + светлый нейтральный фон**, без чёрно-золотой автомобильной эстетики. Сами цвета tenant UI всё равно задаются branding-настройками; речь только о контентных иллюстрациях-подсказках.

---

# 1. Назначение шаблона

Шаблон предназначен для мастеров и компаний, которые занимаются:

- установкой межкомнатных дверей;
- установкой входных дверей;
- заменой старой двери на новую;
- монтажом дверных коробок;
- установкой дверей в существующий проём;
- установкой дверей после ремонта/перепланировки;
- монтажом доборов, наличников и сопутствующих элементов.

Цель: получить от клиента достаточно визуальной информации о проёме, существующей двери и условиях монтажа для первого осмысленного ответа мастера без длинной анкеты и без обязательного точного расчёта стоимости.

---

# 2. Основное действие

**CTA:**

> 📷 Показать дверной проём

Допустимый tenant override:

> 📷 Оценить установку двери

**Заголовок формы:**

> Покажите место установки

**Вводный текст:**

> Сделайте несколько фотографий проёма и места вокруг него. Сначала покажите всё целиком, затем снимите проём ближе и добавьте важные детали — так мастер быстрее поймёт условия монтажа.

---

# 3. Подготовка к съёмке

Перед первым фото показать короткую компактную подсказку:

> Отойдите достаточно далеко, чтобы проём полностью помещался в кадр. Снимайте прямо, при хорошем освещении, не закрывая края проёма мебелью или вещами.

Если старая дверь ещё стоит:

> Если возможно, сфотографируйте дверь и в закрытом, и в открытом положении.

Не превращать этот текст в отдельную длинную страницу.

**Название:**

- немного стены вокруг.

# 5. Размеры

Точные размеры **не делать обязательным условием отправки заявки**. LOOKDO не должен превращаться в самостоятельный замер без мастера.

Но можно предложить простой необязательный блок:

## Ширина проёма

**Ключ:** `opening_width_mm`

Placeholder:

> Например: 900 мм

## Высота проёма

**Ключ:** `opening_height_mm`

Placeholder:

> Например: 2050 мм

## Толщина стены

**Ключ:** `wall_thickness_mm`

Placeholder:

> Например: 120 мм

Все три поля необязательные.

Короткая подсказка:

> Если не уверены — оставьте пустым. Мастер уточнит размеры при необходимости.

Не делать сложную схему замеров в базовом шаблоне. Для отдельного шаблона «Онлайн-замер двери» это можно расширить позднее.

# 6. Что нужно установить

**Ключ:** `door_request_type`

**Заголовок:**

> Что вы хотите сделать?

Варианты:

- Установить новую дверь в пустой проём
- Заменить существующую дверь
- Установить дверь после ремонта
- Установить только коробку / элементы
- Не знаю — хочу обсудить с мастером

Поле необязательно. По умолчанию:

> Не знаю — хочу обсудить с мастером

---

# 7. Тип двери

**Ключ:** `door_type`

**Заголовок:**

> Какая дверь планируется?

Варианты:

- Межкомнатная
- Входная
- Раздвижная
- Другая
- Ещё не выбрал(а)

Поле необязательно.

Не превращать этот блок в каталог дверей или ecommerce.

---

# 8. Референс / выбранная дверь

Отдельный media slot:

**Ключ:** `reference_door`

**Заголовок:**

> Уже выбрали дверь?

**Подсказка:**

> Можно добавить фотографию, скриншот или пример двери, которую вы хотите установить.

**CTA:**

> 🖼 Добавить пример

**media_role:** `reference`

Это изображение хранится отдельно от фотографий объекта.

---

# 9. Видео

Видео разрешено, но не обязательно.

Настройки:

- `video_allowed = true`
- `video_recommended = false`

Подсказка:

> Если по фотографиям сложно показать пространство вокруг проёма, можно снять короткое видео от общего вида к деталям.

Видео не должно быть главным CTA.

---

# 10. Комментарий

**Ключ:** `comment`

**Заголовок:**

> Что ещё важно знать?

**Placeholder:**

> Например: старую дверь нужно снять, новая дверь уже куплена, наличники тоже нужно установить.

Поле необязательно.

# 11. Телефон

**Ключ:** `phone`

**Заголовок:**

> Ваш номер телефона

**Подсказка:**

> Оставьте номер, чтобы мастер мог связаться с вами после просмотра фотографий.

Телефон **обязателен всегда**.

E-mail конечного клиента не спрашивать.

---

# 12. Предпочтительный канал ответа

Необязательно. Показывать только подключённые tenant-каналы:

- В приложении
- По телефону
- VK
- Telegram — если реально подключён tenant

Телефон остаётся обязательным fallback-контактом.

---

# 13. Summary перед отправкой

Не делать отдельный тяжёлый экран подтверждения, если это расходится с `/UI`.

Допустимый компактный summary внутри формы:

> 5 фото · Межкомнатная дверь · замена существующей

Если размеры введены:

> 900 × 2050 мм · стена 120 мм

# 15. Push после отправки

После успешной отправки использовать утверждённое состояние `/UI`.

**Заголовок:**

> Не пропустите ответ

**Текст:**

> Разрешите уведомления, и мы сообщим, когда мастер ответит.

Кнопки:

- Разрешить уведомления
- Не сейчас

Browser/PWA permission запрашивается только после нажатия основной кнопки пользователем.

# 17. Hint illustrations

Шаблон должен иметь собственный набор специализированных подсказок:

```text
hints/opening-overall.png
hints/opening-left.png
hints/opening-right.png
hints/opening-top.png
hints/floor-threshold.png
hints/existing-door.png
hints/problem-detail.png
```

Иллюстрации должны быть:

- понятными без длинного текста;
- одинаковыми по стилю;
- без конкретного бренда дверей;
- без лиц;
- без лишнего интерьера;
- mobile-friendly;
- читаемыми в маленькой карточке;
- выполнены в холодной сине-бирюзовой палитре с нейтральным светлым фоном;
- визуально отличаться от автомобильного набора подсказок;
- использовать выделение нужной зоны рамкой/свечением/акцентной линией.

Файлы `/UI` определяют расположение этих подсказок внутри приложения.

# 18. Tenant overrides

Tenant может упростить шаблон и отключить необязательные элементы:

- размеры;
- тип двери;
- способ установки;
- reference image;
- video;
- отдельные дополнительные photo slots.

Tenant может менять:

- CTA;
- короткие тексты;
- placeholder комментария;
- максимум фото;
- branding/colors самого приложения.

Tenant **не может через этот шаблон** менять:

- основной flow LOOKDO;
- обязательность телефона;
- Messages;
- push flow;
- структуру БД;
- базовую app-like структуру `/UI`.

---

# 19. Наследование

От `repair-finishing-installation.general` наследуются:

- базовый Request Engine;
- camera/gallery flow;
- preview/re-take/delete;
- универсальная структура дополнительных полей;
- телефон;
- submit/success;
- messages;
- push;
- tenant branding;
- API/data model.

Этот шаблон переопределяет только контент и конфигурацию:

- CTA;
- тексты;
- photo slots;
- hint illustrations;
- door-specific optional fields;
- reference image;
- AI phrases;
- recommended summary.

**Создание/редактирование этого шаблона не должно требовать нового Vue-экрана, отдельного API endpoint или новой таблицы БД.**
