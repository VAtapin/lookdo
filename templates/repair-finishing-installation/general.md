# LOOKDO — универсальный шаблон категории «Ремонт, отделка и монтаж»

**Код шаблона:** `repair-finishing-installation.general`  
**Категория:** Ремонт, отделка и монтаж  
**Тип:** универсальный / fallback  
**Родитель:** `BASE_REQUEST_TEMPLATE`  
**Язык исходного контента:** RU  
**Телефон клиента:** обязательно  
**Видео:** разрешено  
**Фото:** 1–5, рекомендуется 3–4  
**Назначение:** используется, если AI понял, что деятельность относится к ремонту, отделке или монтажу, но не найден более специализированный адресный шаблон — например «Установка дверей», «Укладка плитки», «Ремонт стены», «Монтаж окна» и т. п.

> ВАЖНО ДЛЯ CODEX: этот шаблон не создаёт новый экран. Он работает через общий Request Template Engine и строго наследует структуру Tenant App из `/UI`. Меняются только тексты, media slots, универсальные поля и подсказки.

---

# 1. Основное действие

**CTA:**

> 📷 **Показать объект**

Tenant может заменить формулировку на более конкретную, но структура остаётся прежней.

**Заголовок формы:**

> Покажите, что нужно сделать

**Вводный текст:**

> Сделайте несколько фотографий места, помещения, поверхности или элемента, с которым нужно работать. Сначала покажите общий вид, затем нужное место ближе и важные детали.

Не обещать точную цену по фотографии. Фото нужны для первого понимания задачи и ответа мастера.

# 7. Работа с фотографиями

Для каждого слота используются общие действия из BASE_REQUEST_TEMPLATE:

- 📷 Сделать фото
- 🖼 Выбрать из галереи
- Использовать фото
- Переснять
- Удалить
- Добавить ещё фото

После первого фото клиент может сразу перейти дальше. Подсказки направляют, но не создают обязательную длинную анкету.

---

# 8. Видео

**Действие:**

> 🎥 Добавить короткое видео

**Подсказка:**

> Если задачу удобнее показать движением камеры — например пройти вдоль стены, помещения или большого объекта — добавьте короткое видео.

**Статус:** необязательно.

Видео полезно, если:

- объект большой;
- несколько связанных мест;
- нужно показать помещение целиком;
- фото плохо передают взаимное расположение элементов.

`video_allowed = true`  
`video_recommended = false`

# 9. Что нужно сделать

**Заголовок:**

> Что требуется?

**Поле:** textarea  
**Обязательность:** необязательно.

**Placeholder:**

> Коротко опишите, что нужно отремонтировать, установить, заменить, отделать или изменить.

Пример:

> Нужно заменить старую дверь и привести в порядок проём.

Не использовать этот пример в специализированном шаблоне установки дверей — там будет собственный адресный текст.

# 17. Иллюстрации-подсказки

У шаблона должен быть собственный нейтральный набор hint assets:

```text
repair-finishing-installation/general/overall
repair-finishing-installation/general/work-area
repair-finishing-installation/general/detail
repair-finishing-installation/general/another-angle
repair-finishing-installation/general/measurement
repair-finishing-installation/general/video
```

Это не фотографии конкретной профессии, а универсальные схемы/иконки, показывающие правильный тип кадра.

Если специализированный шаблон существует, он заменяет эти hint assets своими — например для двери: общий вид проёма, левый откос, правый откос, верх, порог, рулетка и т. п.

---

# 18. Что tenant может менять

Tenant может изменить или выключить:

- CTA;
- вводный текст;
- дополнительные поля;
- maximum photos;
- video allowed;
- пример комментария;
- собственные пояснения.

Tenant не может менять:

- общий UI flow;
- обязательность телефона;
- camera/upload engine;
- request data model;
- messages/success/push flow;
- структуру Tenant App из `/UI`.

# 20. Fallback-логика

Приоритет:

1. точный специализированный шаблон;
2. близкий специализированный шаблон с достаточной AI confidence;
3. `repair-finishing-installation.general`;
4. если даже категория не определена — Support.

Текст fallback поддержки:

> **Не нашли подходящий шаблон?**
> Напишите нам, чем вы занимаетесь. Мы посмотрим и добавим подходящий вариант.

Кнопка:

> **Написать в поддержку**

---

# 21. Универсальные поля данных

Никаких отдельных таблиц под двери, стены, плитку или окна.

Дополнительные значения хранятся через универсальные request fields.

Для этого шаблона возможны:

```text
object_type
approximate_dimensions
work_description
additional_information
```

Media roles:

```text
overall
work_area
detail
another_angle
measurement
video
```

Создание будущего адресного шаблона должно обходиться конфигурацией и hint assets без нового Vue-компонента, нового API endpoint и новой таблицы БД.
