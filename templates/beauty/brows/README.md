# LOOKDO — шаблон «Брови / Brow Master»

**Код:** `beauty.brows`  
**Категория:** Beauty / уход за внешностью  
**Родительский шаблон:** `beauty.general`  
**Тип:** специализированный адресный шаблон  
**Capability profile:** booking-first + portfolio + before/after + customer retention + AI media

> Шаблон использует общие модули `BOOKING_CUSTOMERS_AI.md`. Он не создаёт отдельные календарь, CRM, messaging backend или AI backend.

## 1. Назначение

Для частных brow-мастеров и небольших brow/beauty-студий: коррекция формы, окрашивание, моделирование и обычный уход за бровями. Permanent Make-up, Microblading, Powder Brows и другие инвазивные/долговременные процедуры не включать автоматически: это отдельные услуги/шаблоны при необходимости.

Главная задача публичного приложения: быстро показать реальные работы мастера и перевести посетителя в запись на свободное время без регистрации.

## 2. Основной пользовательский сценарий

Для этого шаблона `booking` — основной flow, а обычный request/photo flow LOOKDO остаётся дополнительным.

**Путь клиента:** Главная → работы До/После → услуга → свободная дата → время → имя + обязательный телефон → подтверждение → напоминание → визит → повторное приглашение.

**Главный CTA:** `Записаться`

Дополнительные CTA: `Посмотреть работы`, `Написать мастеру`.

## 3. Главная

Первый экран должен быть визуальным, спокойным и персональным, а не похожим на ремонтный сервис или dashboard.

Содержимое:
- имя/бренд мастера;
- портрет мастера или качественное hero-фото результата;
- короткая специализация;
- ближайшее доступное время, если booking включён;
- основной CTA `Записаться`;
- 2–4 лучших пары До/После;
- короткий список основных услуг с ценой, если цена опубликована tenant;
- рейтинг/несколько отзывов, если включены;
- адрес/район;
- кнопка связи через реально подключённый Viber/WhatsApp/Telegram;
- переключатель языка.

Не превращать Главную в длинный лендинг.

## 4. Навигация

Сохраняется общий app shell LOOKDO. Для booking-first шаблона центральное действие = `Записаться`.

Логически клиенту доступны: Главная · Работы · Записаться · Сообщения/Контакт.

## 5. Услуги

Услуги tenant редактирует сам. Seed-примеры без обязательной цены:
- коррекция формы бровей;
- окрашивание бровей;
- коррекция + окрашивание;
- моделирование/оформление;
- консультация/другая услуга.

Для каждой услуги используются общие поля `services`: название, описание, duration_minutes, optional price/currency, repeat_after_days, active, booking_enabled.

Не hardcode цены и длительности в шаблоне.

## 6. Онлайн-запись

Flow:
1. выбрать услугу;
2. при нескольких сотрудниках — выбрать мастера или `Любой`;
3. выбрать дату;
4. показать только реально свободные слоты;
5. выбрать время;
6. имя;
7. обязательный телефон;
8. предпочтительный канал связи;
9. короткий комментарий — необязательно;
10. отдельное согласие на маркетинговые сообщения, если предлагается;
11. подтвердить запись.

Регистрация конечного клиента не требуется.

После записи: дата, время, услуга, мастер, адрес и действия `Добавить в календарь`, `Перенести`, `Отменить`.

## 7. Фото До/После

Это ключевая функция шаблона.

### before
Ключ `before`. Фото области глаз и бровей до работы.

### after
Ключ `after`. Фото после завершения.

### optional_side
Дополнительный боковой/трёхчетвертной ракурс — необязательно.

### Правила съёмки
- лицо/область бровей хорошо освещены;
- без beauty-фильтра;
- камера максимально прямо;
- обе брови видны;
- не закрывать волосы/брови рукой;
- желательно одинаковый свет до и после.

## 8. AI Media Profile

`ai_media_profile = face_brows_alignment`

AI может:
- найти лицо, глаза и брови;
- определить наклон головы;
- выровнять горизонт относительно глаз;
- привести Before/After к одинаковому масштабу;
- центрировать область бровей;
- сделать одинаковый crop/aspect ratio;
- мягко нормализовать экспозицию/white balance;
- подготовить пару для Before/After slider;
- подготовить рекламный коллаж.

AI НЕ МОЖЕТ:
- дорисовывать волоски;
- менять форму/толщину бровей;
- скрывать ошибки мастера;
- ретушировать результат так, чтобы он отличался от фактической работы;
- изменять лицо клиента для демонстрации результата.

Оригиналы всегда сохраняются отдельно от производных изображений.

## 9. Portfolio / Работы

Карточка работы:
- Before/After;
- optional title;
- услуга;
- короткая подпись;
- дата необязательно;
- цена только если tenant хочет публиковать;
- featured flag;
- разрешение клиента на публичную публикацию должно учитываться отдельно.

Основной просмотр — touch-friendly Before/After slider + сетка лучших работ.

## 10. Клиентская карточка мастера

Используется общий customer profile:
- имя;
- телефон;
- preferred language;
- preferred channel;
- история визитов;
- выполненные услуги;
- предыдущие Before/After;
- заметки мастера;
- last_visit_at;
- suggested_next_visit_at;
- consent flags.

Клиент не обязан иметь аккаунт.

## 11. Повторный визит

`repeat_visit_enabled = true`.

Интервал задаётся на уровне услуги/tenant, не hardcode шаблоном.

LOOKDO показывает мастеру клиентов, которым подходит время повторного визита, и предлагает подготовить персональное приглашение.

## 12. Напоминания

Используется общий reminder engine.

Рекомендуемый default: сервисное напоминание за 24 часа; второе короткое напоминание может включаться tenant.

Действия клиента: `Подтвердить`, `Перенести`, `Отменить`.

## 13. Освободившееся окно

`vacancy_fill_enabled = true`.

После отмены мастер может нажать `Заполнить окно`. LOOKDO создаёт короткое сообщение с датой/временем, услугой при необходимости и deep link непосредственно на этот слот. После бронирования слот больше не предлагается.

## 14. Группы клиентов

Используется общий segmentation engine. Полезные динамические сегменты:
- постоянные;
- новые;
- давно не приходили;
- пора повторить услугу;
- по языку;
- по услуге;
- согласились на маркетинг.

Маркетинговая рассылка только при соответствующем consent.

## 15. Каналы

Шаблон рекомендует, но не требует:
- Viber;
- WhatsApp;
- Telegram;
- Web Push/PWA.

Показывать только реально подключённые tenant-каналы. Телефон остаётся обязательным fallback согласно ядру LOOKDO.

## 16. AI Communication Assistant

AI использует язык клиента и контекст, но отправка подчиняется общим правилам communication engine.

Сценарии:
- подтверждение/напоминание о Termin;
- приглашение на повторный визит;
- заполнение свободного окна;
- короткий ответ на типовой вопрос;
- текст публикации из новой работы;
- адаптация одного текста на UA/RU/DE.

AI не должен придумывать цену, скидку, медицинские обещания или услугу, которой нет у tenant.

## 17. AI публикации

Из пары Before/After LOOKDO может подготовить:
- Story 9:16;
- квадрат/портрет social post;
- карточку для Viber/WhatsApp/Telegram;
- брендированный preview с названием услуги и optional price;
- QR/deep link `Записаться`.

Мастер подтверждает публикацию/рассылку.

## 18. Smart Today для мастера

На мобильном главном экране мастера приоритетны действия, а не аналитические графики:
- записи сегодня;
- следующий клиент;
- свободные окна;
- неподтверждённые записи;
- клиенты для повторного приглашения;
- новые Before/After, ещё не опубликованные;
- быстрые действия `Напомнить`, `Заполнить окно`, `Создать публикацию`.

## 19. Локализации

Для первого реального Brow tenant обязательны:
- `uk` — украинский;
- `ru` — русский;
- `de` — немецкий.

Все строки template/booking/service labels локализуемые. Язык клиента сохраняется в customer profile.

Примеры CTA:
- UK: `Записатися`, `Роботи`, `Обрати час`, `Перенести`, `Скасувати`;
- RU: `Записаться`, `Работы`, `Выбрать время`, `Перенести`, `Отменить`;
- DE: `Termin buchen`, `Arbeiten`, `Zeit wählen`, `Verschieben`, `Absagen`.

## 22. UI reference — обязательно

Папка `UI/` этого шаблона должна содержать минимум три визуальных reference:
1. `01-home` — Главная Brow Master: бренд/мастер, hero, ближайшее окно, CTA записи, лучшие Before/After, услуги;
2. `02-booking` — выбор услуги/даты/времени без регистрации;
3. `03-master-today` — мобильный рабочий экран мастера: записи, свободное окно, повторные клиенты, публикации.

Эти изображения определяют композицию именно brow-сценария, но используют общий LOOKDO app shell и компоненты. Это не отдельный frontend.

## 23. Критерий готовности

Шаблон считается готовым, если Brow tenant можно подключить конфигурацией без создания Brow-specific controller/API/table, клиент может увидеть реальные работы и записаться без регистрации, мастер получает календарь/клиента/напоминания через общие модули, а AI корректно выравнивает Before/After без изменения фактического результата.
