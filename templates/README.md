# LOOKDO — библиотека шаблонов заявок

Эта папка является **единственным каноническим местом** для описания шаблонов заявок LOOKDO.

## Главное правило

Нельзя разносить логику профессий по разным Vue-компонентам, controller, migration или случайным config-файлам.

Все шаблоны должны строиться от одного базового движка и храниться централизованно здесь как конфигурации/описания, которые затем синхронизируются/seed-ятся в БД.

### Структура

- `BASE_REQUEST_TEMPLATE.md` — неизменяемое ядро всех заявок.
- `base-request-template.json` — машинно-читаемая схема базового шаблона.
- далее отдельные файлы конкретных шаблонов, например:
  - `automotive-steering-wheel.json`
  - `repair-door-installation.json`
  - `appliance-washing-machine.json`

При создании нового шаблона **не копировать весь frontend**. Нужно клонировать только конфигурацию шаблона и изменить разрешённые поля/тексты/подсказки.

## Архитектурное требование для Codex

Новый шаблон деятельности должен добавляться без:

- нового Vue-экрана;
- нового API endpoint;
- новой таблицы БД;
- отдельного controller только под профессию;
- дублирования upload/chat/push логики.

Если для новой профессии требуется новый экран или новая таблица, сначала проверить, нельзя ли выразить отличие через универсальные поля и конфигурацию шаблона.

## База данных

В runtime шаблоны хранятся в БД и редактируются через Super Admin. Git-файлы в этой папке являются исходной/seed-документацией и удобной точкой разработки/ревью.

Рекомендуемая модель:

```text
request_templates
- id
- code
- category_id
- name
- description
- primary_action_label
- title
- intro_text
- photo_min
- photo_max
- video_allowed
- video_hint
- fields_schema_json
- media_slots_json
- submit_text
- success_text
- enabled
- sort_order
- version
```

Локализуемые тексты хранить либо в отдельных translation records, либо в JSON по локалям, но не hardcode в Vue.

## Неизменяемая часть vs изменяемая часть

**Неизменяемая часть** определяется `BASE_REQUEST_TEMPLATE.md` и реализуется один раз.

**Изменяемая часть** каждого конкретного шаблона:

- название шаблона;
- категория;
- CTA/заголовки/подсказки;
- количество и назначение фото-слотов;
- разрешение короткого видео;
- несколько дополнительных универсальных полей;
- тексты комментария/submit/success;
- ключевые слова и фразы для AI-классификации.

Телефон клиента, общая отправка, статусы, media storage, сообщения, push, success flow и API-контракт остаются общими.
