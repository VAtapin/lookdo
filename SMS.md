# LOOKDO — SMS конечным заказчикам

SMS — дополнительный канал только для конечного заказчика. Владелец/мастер получает рабочие уведомления через push. Автоматической доплаты за превышение лимита нет: при достижении месячного лимита новая SMS не ставится в очередь.

## Настройка платформы

В Super Admin открыть `Einstellungen` → `SMS an Endkunden`:

- включить интеграцию SMS;
- выбрать `seven.io`;
- указать имя отправителя, API Key и Signing Key;
- включить нужные события;
- сохранить и проверить соединение.

Секреты хранятся в базе зашифрованными через `APP_KEY` и не возвращаются клиентскому API. В seven.io нужно создать JSON webhook для события DLR по адресу, показанному в админке (`https://lookdo.app/api/webhooks/seven/sms`). Подпись и защита от повторного nonce проверяются до обработки отчёта.

## Тарифы

В каждом тарифе задаются две независимые возможности:

- `SMS an Endkunden` — разрешение отправки;
- `SMS pro Monat` — строгий месячный лимит.

Если разрешение выключено или лимит равен нулю, SMS не отправляются. Превышение не тарифицируется автоматически.

## События

Разрешены только важные события:

- `request_received` — заявка получена;
- `master_replied` — мастер ответил, можно открыть ссылку;
- `work_ready` — работа готова;
- `agreement_reminder` — напоминание о договорённости или записи.

Часть 2 должна ставить сообщение через `SmsService::queueImportant(...)` с уникальным ключом идемпотентности события. Повтор того же события для того же Tenant не создаёт вторую отправку.

## Очередь и журнал

Отправка выполняется Laravel queue worker. Для production должен постоянно работать процесс из `DEPLOYMENT_PLESK.md`; после обновления выполняется `artisan queue:restart`.

Super Admin → `SMS-Protokoll` показывает Tenant, событие, маскированный телефон, статус, количество частей, стоимость, Provider ID или ошибку. Полный номер, текст сообщения и payload провайдера зашифрованы. Статусы доставки обновляет подписанный DLR webhook seven.io.
